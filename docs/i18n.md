# 双语站（en / zh）架构说明

> 生效日期：2026-09-29 · 适用版本：Next.js 16.3.2 + `output: 'export'`（Cloudflare Pages 静态托管）

## 1. 语种与 URL 约定

| 语种 | 路径 | `<html lang>` | 角色 |
|---|---|---|---|
| 英文 | `/`、`/method`、`/platform/openrouter` … | `en` | 默认语种（占根路径，无前缀） |
| 中文 | `/zh`、`/zh/method`、`/zh/platform/openrouter` … | `zh-CN` | 第二语种 |

英文占根路径的原因：目标流量是海外英文检索；同时**根路径保持真实页面**，不需要任何重定向，也不动已经存在于 `/` 的收录。

`public/_redirects` 只保留一条安全网：`/en` 与 `/en/*` 301 到无前缀英文版。

## 2. 为什么是「两个路由组」而不是 `app/[locale]/`

这是实测结论，不是偏好：

| 方案 | 静态导出下的实测结果 |
|---|---|
| `app/(en)/**` + `app/(zh)/zh/**`（当前方案） | ✅ 根路径正常产出 `out/index.html`，两语种各自静态 `<html lang>` |
| `app/[locale]/**` | ❌ 产物里**没有 index.html**，站点根 404；`app/page.tsx` 里 `redirect()` 只能产出客户端跳转空壳（无 meta refresh，Bing 不吃 JS）；`app/[[...locale]]/` 被框架直接拒绝（`Optional catch-all must be the last part of the URL`） |

代价是路由文件按语种各一份（18 个），但每个只有几行——页面主体全在 `src/views/*`，不存在逻辑重复。

## 3. 三层文案归属

| 层 | 位置 | 说明 |
|---|---|---|
| UI 文案 | `src/locales/{en,zh}.json` | 按钮、标题、表头、提示语等；`getDictionary(locale)` 取用，键结构由 TS 校验 |
| 数据译文 | `src/data/i18n/en.json` | 平台/免费额度/资源/福利/抽查备注的英文覆盖层，按 id / slug 索引 |
| 中文基线 | `src/data/*.json` | 原始内容；**Contract v1 冻结，且 platforms / perks / authenticity 会被探测脚本重写** |

覆盖层缺项时自动回退中文基线（`src/lib/content.ts` 的 `mergeEntry`），所以漏译不会让英文页出现空字段，只会露出中文——由 `npm run i18n:check` 和 `npm run verify:site` 兜住。

## 4. SEO 口径

- canonical 与 sitemap 一致：**绝对 URL、无尾斜杠**（CF Pages 对带尾斜杠的路径返回 308，写尾斜杠会触发 GSC「网页会自动重定向」）。
- 每个页面（含中文页自己）都输出三件套 hreflang：`en` / `zh` / `x-default`，`x-default` 指向英文版；双向互相指向。
- `src/app/sitemap.ts` 对 78 条路由 × 2 语种输出 156 条 `<url>`，每条带 `xhtml:link` alternates。
- 语言切换器渲染成真实 `<a hrefLang>`（可被爬虫发现），不做浏览器语言自动跳转（自动跳转会干扰抓取）。

## 5. 新增内容的操作路径

1. 中文数据改 `src/data/*.json`（既有流程不变）。
2. 英文译文加进 `src/data/i18n/en.json` 对应小节，键为平台 `id` / 条目 `slug`。
3. `npm run i18n:check` 看覆盖率；`npm run build && npm run verify:site` 验收。
4. UI 新文案：同时加到 `src/locales/en.json` 与 `src/locales/zh.json`（少键会 TS 报错）。

## 6. 部署闸门

`.github/workflows/deploy_pages.yml` 在部署前依次执行：

| 步骤 | 阻断 | 作用 |
|---|---|---|
| `npm run lint` / `npm run build` | 是 | 既有 |
| `npm run contract:check` | 是 | 既有：Contract v1 数据契约 |
| `npm run i18n:check` | 否（仅日志） | 漏译只回退中文，不阻止发布 |
| `npm run verify:site` | 是 | 内链 404 / canonical 尾斜杠 / hreflang 缺失 / 英文页中文残留 |

注意：新增平台若未补英文译文，`verify:site` 会因「英文页出现中文字符」拦下部署——这是有意为之（避免英文页出现半中文），按提示跑 `i18n:check` 定位即可。
